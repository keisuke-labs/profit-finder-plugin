# pf-soldout

## 目的

カードのメルカリ候補に、売り切れの印を付ける、または外します。商品ページで確かめた事実だけを記録し、推測では付けません。書き込みを伴うため、実行前に対象と内容を示して利用者の OK を取ります。

## 手順

1. `card_id` が分からなければ、`pf_ledger_search` で対象のカードを探します。
   - `exclude_listed` は「出品済みのカードを除く」指定で、既定は true です。`min_profit` は省略すると最低利益の絞り込みが有効になります。そのため、出品済みや利益の低いカードは、既定のままでは見つかりません。
   - 見つからなければ、`exclude_listed: false` と `min_profit: {enabled: false}` で探し直します。
   - 該当するカードが複数あるときは、一覧で示して利用者に選んでもらいます。0 件のときは、書き込まずにその旨を伝えます。
2. `pf_ledger_get_card`（`card_id`）で、メルカリ候補の `mercari_id`・`url`・`price_jpy` と `sold_out_listings` を取得し、対象の候補を確定します。
   - 売り切れにする（付ける）ときは、メルカリ候補のうち `sold_out_listings` に無い候補を、`mercari_id`・`url`・`price_jpy` の一覧で示して、利用者に選んでもらいます。
   - 売り切れを外すときは、`sold_out_listings` にある候補を一覧で示して、利用者に選んでもらいます。メルカリ候補の一覧に売り切れ済みの候補が含まれるかどうかには頼りません。
   - 候補が 1 件だけのときも、その候補で間違いないかを示して確定します。
3. 現在の状態を確かめます。利用者が指定した候補がすでに売り切れ済み（`sold_out_listings` にある）なのに「付ける」という依頼、または売り切れが付いていない候補に「外す」という依頼なら、「変更なし」と伝えて書き込みません。
4. 利用者が商品ページで売り切れ（または在庫の復活）を確かめたかを聞きます。
   - 商品ページで見たと明言していれば、確認済みとして扱います。「売り切れだった」だけでは何で確かめたか分からないため、候補が 1 件のときも、商品ページで確かめたかを聞きます。
   - 確かめていないときは、URL を渡して確認を頼みます。自動で確かめたいときは `pf-stock-check` を案内します。この段階では書き込まず、推測で付けません。
5. 確かめたと分かったら、対象（カードと `mercari_id`、`url`、`price_jpy`）と「売り切れにする／外す」を示して OK を求めます。
6. OK を得てから、`pf_ledger_set_soldout`（`card_id`、`mercari_id`、`sold_out`）を呼びます。`sold_out` は、付けるなら `true`、外すなら `false` です。呼び出しは候補ごとに 1 回です。
7. 結果を伝えます。同じ値を再指定した場合は何も書き込まれないため、その旨も伝えます。エラーが返ったときは、その旨と対象を伝え、成功したとは言いません。

## 書き込み前の確認

`pf_ledger_set_soldout` は書き込みです。候補ごとに、次の 2 つがそろうまで呼びません。

- 利用者が商品ページで状態を確かめたこと
- 対象と内容（「売り切れにする」または「外す」）を、`url`・`price_jpy` も併せて示したうえでの、利用者の OK

複数の候補を扱うときは、全件を一覧にして示し、1 回の OK でまとめて実行してかまいません。ただし、一覧には対象の全件を載せます。

一括のときも、商品ページで確かめたかどうかは候補ごとに確認します。「全部売り切れだった」の一言だけでは足りないので、候補ごとに確認済みかを示してもらいます。呼び出しは候補ごとに 1 回で、OK を得て、かつ確認済みの候補だけ実行します。

## 失敗時

ツールが見つからない、または未認証のときは、推測で答えません。`/mcp` で pf を認証するよう案内して、そこで止まります。

書き込みでエラーが返ったときは、そのエラーの内容と対象を伝えます。成功したとは言わず、利用者の指示を仰ぎます。
