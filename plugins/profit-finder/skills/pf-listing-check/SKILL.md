# pf-listing-check

## 目的

run ごとの商品リストの行に対して、出品対象にする（チェック）、見送りにする、見送りから戻す、の 3 つの操作を行います。いずれも書き込みを伴うため、実行前に対象と内容を示して利用者の OK を取ります。

## 手順

1. 対象の行を探します。`pf_listings_list`（`include_untracked: true`、`run_dir` は省略）を呼び、利用者が示した商品名などから行を特定して、`run_dir`・`row_id`・`status`・`version`・`mine` を控えます。未チェックの行は `status`・`version` が null です。
   - 該当する行が複数あるときは、商品名・想定利益・`status` を一覧にして示し、利用者に選んでもらいます。
   - 1 ページ目に見つからないときは、`cursor` で続きのページを探します。それでも見つからなければ、書き込まずにその旨を伝えます。
2. 控えた `status` と利用者の依頼を、次の表に当てはめて、実行できる操作かを判断します。

   | 行の状態 | 出品対象にする | 見送る | 戻す |
   |---|---|---|---|
   | 未チェック（`status` が null） | `pf_listing_check` | できない（未チェックの行は見送り・復帰できない、と伝える） | できない（同） |
   | candidate／exported | 自分の行（`mine` が true）なら既に対象なので「変更なし」と伝えて書き込まない。他人の行（`mine` が false）は 409 になるので書き込まない | `pf_listing_withdraw` | できない（見送りではないため） |
   | withdrawn | `pf_listing_restore` を使う（`pf_listing_check` ではない） | 既に見送りなので「変更なし」と伝えて書き込まない | `pf_listing_restore` |

   - 状態に合わない操作は、OK を求める前に利用者へ理由を伝え、書き込みません。
   - `status` が null でない行で `mine` が false のとき、`pf_listing_check` は 409 になるので実行しません。
3. 実行できる操作について、商品名・想定利益・「現在の状態 → 変更後の状態」を示し、OK を求めます。
4. OK を得てから、操作に応じて次のツールを 1 回ずつ呼びます。
   - 出品対象にする: `pf_listing_check`（`run_dir`、`row_id`）
   - 見送りにする: `pf_listing_withdraw`（`run_dir`、`row_id`、`version`）
   - 見送りから戻す: `pf_listing_restore`（`run_dir`、`row_id`、`version`）
5. 結果（変更後の `status` と `version`）を利用者に伝えます。

### 注意

- 見送り・復帰は、チェックした本人か admin だけが行えます。この注意は `status` が null でない行にだけ当てはまります（未チェックの行は、そもそも見送り・復帰の対象ではありません）。`status` が null でなく `mine` が false の行の見送り・復帰は admin だけなので、実行前にその旨を伝えます。
- 自分が既にチェックした行に `pf_listing_check` を再実行しても、状態は変わらず現在の行が返ります。ただし、手順 2 のとおり、既に対象の行には書き込まず「変更なし」と伝えます。
- ほかの人（管理画面を含む）がチェック済みの行への `pf_listing_check` は 409 になります。

## 書き込み前の確認

`pf_listing_check`・`pf_listing_withdraw`・`pf_listing_restore` は書き込みです。実行前に、対象（商品名・`row_id`）と内容（現在の状態 → 変更後の状態）を示して、利用者の OK を取ります。OK が無いまま実行しません。

複数の行を扱うときは、全件を一覧にして示し、1 回の OK でまとめて実行してかまいません。ただし、一覧には対象の全件を載せます。一部だけを示して全件分の OK を取ることはしません。実行できない行（変更なし、状態に合わない操作）は、一覧の中でその旨を示し、書き込みの対象に含めません。

まとめて実行している途中で 409 やエラーが出たら、そこで止めます。実行済みの行と未実行の行を分けて伝え、利用者の指示を仰ぎます。

## 失敗時

ツールが見つからない、または未認証のときは、推測で答えません。`/mcp` で pf を認証するよう案内して、そこで止まります。

409 や権限のエラー（admin でない利用者が他人の行を見送る・戻す場合など）は、自動で再試行しません。エラーの内容を伝え、409 や権限のエラーのときは `pf_listings_list` を読み直した現在の状態も伝えて、利用者の指示を仰ぎます。
