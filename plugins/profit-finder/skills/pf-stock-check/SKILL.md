# pf-stock-check

## 目的

台帳のカード 1 枚に紐づくメルカリ候補が、いま販売中かどうかを実ページで確かめます。売り切れと読めた候補は、利用者の確認を取ってから台帳で売り切れにします。

調べるのは Claude in Chrome で開いた実ページです。ウェブ検索や保存済みの情報で代用しません。

## 手順

1. 対象のカードの `card_id` を決めます。利用者が示していなければ、`pf_ledger_search` や `pf_overview` で探して、どのカードか利用者に確かめます。`pf_ledger_search` は既定で出品済みのカードと利益の低いカードを除くので、見つからなければ `exclude_listed: false` と `min_profit: {enabled: false}` で探し直します。`pf_ledger_search` には名前で絞る引数が無いので、`limit` と `cursor` で読み進め、名前で照合します。
2. `pf_ledger_get_card`（`card_id`）でカードを取得します。対象は `mercari.listings` の候補（販売中の候補だけで、売り切れの目印が付いたものは最初から入っていません）です。各候補の `url` と `mercari_id` を集めます。
3. `mercari.listings` が空（候補が 0 件）なら、その旨を伝えて終えます。このとき `mercari.sold_out_listings` の件数も添えて、理由を伝えます（例「販売中の候補は 0 件です。売り切れの目印が付いた候補が 3 件あります」）。この場合はタブを作りません。
4. Claude in Chrome で、`tabs_context_mcp` でタブの状況を確かめ、空のタブが用意されていればそれを使い、無ければ新しくタブを作ります。人がログイン済みの Chrome を使い、ログイン・購入・出品の操作はしません。Claude in Chrome が使えないときは、その旨を伝えて止まります（ウェブ検索で代用しません）。
5. 集めた候補の商品ページを 1 件ずつ開いて読み、販売中か売り切れかを判断します。開くのは各候補の `url` をそのままです。`mercari_id` から URL を組み立てません（メルカリ Shops の候補は URL の形が違います）。売り切れの表示があれば売り切れとする基準は、Shops のページでも同じです。
   - `mercari.best_mercari_id` が null でなければ、その候補を最初に開きます。残りの候補と、null のときの全候補は、一覧の順に開きます。
   - 開くのは 1 回の調査で 20 件までです。20 件で止め、開かなかった候補が何件あるかを利用者に伝えます。
   - bot 対策の画面やログイン要求に当たったら、サイトへの負荷とアカウントのリスクを避けるため、それ以降のページは開かず、その場で止めます。当たったページと開かなかった候補は「判定できない」として表に入れ、止めた理由を利用者に伝えます。そこまでに売り切れと読めた候補は、通常どおりタブを閉じてから OK を求めて構いません。
6. 各候補を次の 4 つに分けて、表で示します（`mercari_id`・`url`・価格・判定）。
   - 販売中
   - 売り切れ: 商品ページに売り切れの表示（「売り切れ」「SOLD」など）があるもの。売り切れかどうかは、その商品自身の表示（商品名や購入ボタンの近く）で判断し、おすすめ欄などに出る別の商品の「売り切れ」は数えません
   - ページなし（削除済み）: 「ページが見つかりませんでした」などの表示が出た、または 404 だったもの。書き込まず（売り切れの目印は付けません）、買えない状態であることを伝えます
   - 判定できない: ログインを求められた、bot 対策の画面が出た、読み取りに失敗した、読み込めないページなど。売り切れとはみなしません
7. 全件を読んで表を作ったら、利用者に OK を求める前に、使ったタブを閉じます。書き込みにタブは要らないためです。途中で止めたときも閉じます。
8. 売り切れと読めた候補があれば、「書き込み前の確認」に従って利用者の OK を取り、売り切れにします。

## 書き込み前の確認

書き込むのは `pf_ledger_set_soldout`（`card_id`、`mercari_id`、`sold_out: true`）だけです。

- 商品ページに売り切れの表示があった候補だけを対象にします。推測では付けません。「ページなし」「判定できない」の候補は書き込みません。
- 実行する前に、対象の `mercari_id` と `url`、「売り切れにする」という内容を示し、「売り切れにしますか」と尋ねて利用者の OK を取ります。OK が無いまま実行しません。
- 対象が複数のときは、全件を一覧にして 1 回で OK を取って構いません。一部だけを省略せず、対象は全件を示します。
- OK を得た候補だけを実行します。一部の候補だけ OK なら、その分だけを実行します。
- `pf_ledger_set_soldout` がエラーを返したときは、その旨と対象の候補を伝え、成功したとは言いません。
- 価格は書き戻しません。調べた価格は会話の中で使うだけで、保存しません。

## しないこと

- 価格の書き戻し
- 売り切れを外す操作（外すときは `pf-soldout` を使います）
- ログイン・購入・出品の操作
- ウェブ検索による代用

## 失敗時

- pf のツールが見つからない、または未認証のときは、推測で答えず、`/mcp` で pf を認証するよう案内して止まります。
- Claude in Chrome が使えないときは、その旨を伝えて止まります。
- 商品ページの読み取りに失敗した候補は「判定できない」として表に載せ、書き込みません。
- bot 対策の画面やログイン要求に当たったときは、それ以降のページを開かずに止め、当たったページと開かなかった候補を「判定できない」として表に載せます。止めた理由を伝えます。
